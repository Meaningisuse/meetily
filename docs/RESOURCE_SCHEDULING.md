# 录音优先的本地资源调度

实现入口：`resources.rs`、`jobs/scheduler.rs`、`audio/recording_commands.rs`、`audio/batch_limits.rs`、`audio/catchup.rs` 和 `summary/llm_client.rs`。

## 准入规则

每个 AppState 的 JobService 创建一份 ResourceScheduler；录音、摘要、导入、重转写、元数据解码回退和保存音频补转写从该实例取得许可。测试各自创建实例，避免全局测试锁互相污染。原摘要队列的单并发、16项队列上限和来源版本校验保持有效。

| 场景 | 行为 |
|---|---|
| 开始录音 | 在同一临界区登记录音意图；新本地工作随即不能入场 |
| 已有本地工作 | 等待它自然结束，最多15秒；界面显示等待且尚未采集，IS_RECORDING仍为false |
| 15秒未取得资源 | 返回可重试BUSY，撤销该次意图，不产生录音session，也不自行取消原工作 |
| 录音初始化／活动／停止收尾 | 持有资源许可；实时转写和最终保存都属于录音生命周期 |
| 新本地摘要 | 保留queued，等录音和停止收尾结束；可使用现有摘要取消入口取消排队 |
| 新导入／重转写／解码回退／保存音频恢复 | 立即返回BUSY，使用既有错误路径；不会重置其他任务的取消标志或卸载它的引擎 |
| 固定云服务摘要 | 不占本地许可，仍受原摘要串行队列约束；不会越过排在它前面的本地摘要 |

这是准入优先，不是中途强占。正在运行的任务不被丢弃，也没有自动暂停／恢复协议。录音请求超时后需要重试；15秒是资源等待预算，不是设备初始化的总耗时上限。界面只有在原生采集真正启动后才进入RECORDING。

固定云服务为OpenAI、Claude、Groq、OpenRouter。内置AI、Ollama、自定义OpenAI兼容服务及未知类别都保守视为本地；包括配置成远端地址的Ollama和自定义服务，以避免只判断localhost漏掉DNS／代理指向本机的情况。provider使用任务入队时冻结的参数，不重新读取全局设置。

## 许可与清理的生命周期

录音两条start路径都先取得资源，再取engine lifecycle锁。采集启动后许可随全局manager生命周期移交，stop取走后继续持有，直到转写worker退出、引擎清理及保存收尾完成。catch-up同样先资源准入再engine lifecycle锁，完成后卸载本地STT模型。

批处理继续使用可克隆lease。spawn_blocking中的解码／重采样／VAD及未消费的完成结果都持有同一许可，异步等待者消失不会提前放行第二项工作。异常中断且没有完成清理证据时，调度器保留uncertain状态。

本地摘要的取消只阻止后续请求，已经发出的HTTP请求会继续读完当前响应体，丢弃取消后的结果，再释放许可。取消状态可能先显示在业务任务中；这不代表本地计算已经停止。HTTP仍使用300秒请求超时，超时不是外部推理已终止的证据。

内置helper当前推理也等待结束，再执行有界shutdown写入和已确认的wait／kill／wait；每次生成调用后退出helper，释放本地模型驻留。分块摘要可能因此增加模型重载时间，此处优先保证资源归还可确认。用户管理的Ollama／自定义服务不会由应用结束进程或强制卸载模型。

请求完成证据与摘要业务成功分离：尚未发请求的参数错误、完整响应后的length／JSON／正文错误、完整HTTP错误响应都可正常释放许可。传输失败、响应体未读完、任务异常drop、panic或helper退出无法确认则进入uncertain；不能把HTTP future被drop当作推理停止。

## 保守失败边界

uncertain会拒绝新的录音和本地工作，提示确认本地服务已停止并重启Meetily。没有自动清除此状态的健康检查，因为服务可响应不代表没有后台推理。以下录音情况也使用这一策略：

- 设备／模型预检失败发生在启动后台工作之前，普通许可正常释放。
- 已进入RecordingManager.start_recording后失败，现有rollback不能统一证明全部后台任务退出，因此保留uncertain。
- stream或pipeline停止错误向上传播；继续执行转写和保存收尾，但不能把资源声明为空闲。
- worker意外退出、保存超时或停止过程被异常中断，同样不能自动放行。
- 普通保存返回错误且采集、pipeline和worker清理已经确认时，可释放许可，保留原有恢复材料及错误结果。

调度器约束本应用发起的任务，不限制其他程序启动的推理、用户管理服务的模型驻留或整机GPU／RSS。它也不改变[批处理PCM预算](BATCH_AUDIO_LIMITS.md)。真实设备、长会议和效果验收仍需独立完成。

## 自动化验证

回归覆盖原子录音意图与批处理竞争、队列防插队、超时／放弃等待、异常drop／panic、queued摘要取消和来源冲突、云端摘要与录音许可并行、batch阻塞任务及完成结果的许可保持。合成HTTP服务验证取消后响应体尚未完成时不能放行，排空后才放行；传输中断和任务abort不能伪装空闲；参数／length／JSON／完整500错误不误封禁。合成子进程验证helper清理需要观察到退出状态；清理结果注入覆盖stream和pipeline错误传播。

这些测试不启动真实麦克风、真实会议或真实模型，没有验证真实设备rollback故障、整机内存峰值、录音质量和外部服务取消协议。具体命令及结果见[验收证据](ENHANCEMENT_ACCEPTANCE.md)。
