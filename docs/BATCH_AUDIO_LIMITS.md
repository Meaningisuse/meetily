# 导入与重转写的音频内存边界

适用实现：`audio/batch_limits.rs`、`decoder.rs`、`import.rs`、`retranscription.rs`、`vad.rs`。本轮采用预算内整段处理，超限返回错误；没有实现任意时长的全流式转写。

## 默认限制

| 限制 | 默认值 | 用途 |
|---|---|---|
| 应用层 PCM 工作预算 | 2 GiB | 约束源 PCM、转换结果和 VAD 输出的容量 |
| 固定 scratch 预留 | 256 MiB | 单包复制、一个 sinc 窗口、VAD 状态和当前段拆分开销 |
| 单个已解码 packet | 16 MiB | 在创建 SampleBuffer 和追加应用 PCM 前检查 |
| 实际采样率／声道 | 1–192,000 Hz／1–32 声道 | 拒绝非法和不支持的实际格式；解码中途格式变化也拒绝 |
| FFmpeg 临时 WAV | 512 MiB | 参数限额加运行中、退出后的文件大小检查；触限结果不得视为完整音频 |
| 源文件 | 20 GiB | 独立的磁盘输入限制，不表示文件可完整处理 |
| 同时运行的音频批处理 | 1 | 导入、重转写及元数据失败后的解码回退共享准入 |

**2 GiB 不是整个进程的 RSS 保证。** 模型、codec 内部申请、分配器、实时录音及推理内部缓冲不受这份应用 PCM 预算完整约束。FFmpeg 大小轮询可能存在有限超调，它不是操作系统硬配额。

## 分配规则

解码准入按实际格式计算最大源容量。设源 interleaved f32 容量字节为 D，按帧数向上取整预测的 16 kHz mono 容量字节为 T，要求 `2D + 2T + scratch ≤ 工作预算`。使用宽整数计算并检查溢出；Vec 采用可失败的有界增长，同时限制 capacity，不能依靠长度检查后无限扩容。

容器 metadata 可以提前拒绝明显超限的文件，但不能授权运行时无限增长。每个实际解码 packet 都独立检查格式、容量及累计样本；容器低报无法绕过实际上限。容器高报则可能导致保守拒绝，不承诺透明修复所有错误 metadata。

消费式转换直接移动单声道 buffer，多声道原地取均值并压缩，随后原地归一化。非16 kHz数据按既有60秒窗口、100毫秒 overlap和顺序 cross-fade执行高质量 sinc 重采样，每个窗口合并后释放。目标 Vec 的最大容量另按仍存活的源 allocation 计算；重采样失败直接报错，不退回全量分配或返回错误采样率的数据。

VAD检查输入 capacity与累计输出段 capacity之和，加 scratch 后不超过预算。VAD后的普通段直接移动，仅拆分当前过长片段；推理逐段消费 samples，释放已处理音频。不得通过丢弃音频片段满足限额。

共享 lease 覆盖批处理和引擎清理。每个阻塞任务及其完成结果也持有 lease，防止异步调用方取消后，旧任务仍保留 PCM 而新批处理开始。争用失败走现有错误事件，不重置另一批的取消标志，也不卸载其引擎。

## 可接受长度与失败行为

上限取决于源格式。按默认解码预算的算术估计，16 kHz单声道约122分钟，48 kHz双声道约35分钟；这不是时长承诺，也没有计入特定格式的临时转换限制。120分钟16 kHz单声道通过预算算术测试，不代表已经实测两小时导入的性能或峰值RSS。高采样率、多声道或更长文件可能需先裁剪或降采样。

超限返回明确的内存预算错误，提示裁剪音频或降低采样率／声道。不会把触限文件当作完整输入，不会在重转写的准备阶段失败后进入替换旧转写的事务。后者已核对控制流，尚无真实应用旧库的故障注入验收。

解码在 packet 间检查取消，重采样在固定窗口前后检查取消，VAD在每个固定输入块检查取消。FFmpeg轮询取消时 kill 并 wait回收进程，临时 WAV通过TempPath清理。取消不是毫秒级保证；一个sinc窗口或一个codec调用仍需返回。元数据回退没有单独的用户取消来源，但受同一预算和准入约束。

## 验证边界

回归使用小预算和合成WAV验证实际解码拒绝；验证越界扩容前拒绝、packet上限、上采样预算、整数边界、归一化和消费式移动、sinc抗混叠及取消、VAD输出预算、片段时间保留、FFmpeg触限文件拒绝和临时清理、子进程回收、取消等待者及完成结果释放前的lease保持。

这些测试不使用真实会议、麦克风或收费provider，也不证明长会议识别质量、整应用RSS或业务验收。具体命令与实际结果见[验收证据](ENHANCEMENT_ACCEPTANCE.md)。
